# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Vanilla JavaScript Tetris. No build step, no dependencies, no package.json. Three files: `index.html` (DOM/canvas structure), `style.css` (dark retro theme), `game.js` (all game logic, ~300 lines).

## Running the game

Open `index.html` directly in a browser, or serve it locally:

```bash
python3 -m http.server 8000
# or
npx serve .
```

There are no build, lint, or test commands — this project has none configured.

## Architecture (`game.js`)

Everything lives in one file with module-level mutable state (`board`, `current`, `next`, `score`, `lines`, `level`, `paused`, `gameOver`, `dropInterval`, etc.) — no classes, no modules.

- **Board model**: `ROWS × COLS` matrix; each cell is `0` (empty), a color index `1–8` or `11–14` identifying which piece locked there, or `WILD` (10) for a Tinte wildcard. `POWERUP` (9) only ever appears on the falling piece — it is never merged onto the board.
- **Pieces**: defined as matrices in `PIECES` (not all square — the pentominoes and the Single are rectangular/1×1). Rotation is done via `rotateCW` (transpose + reverse), not by storing pre-rotated states. Index 8 is the "Nut" — a non-standard 3×3 piece (`NUT` constant) with an empty center cell. Its center hole is drawn as a ring (`drawNutHole`) only while the piece is in flight (current piece, ghost, and next-preview); once locked the hole is just an ordinary empty board cell. Indices 11–13 are three pentominoes (`PLUS`, `U_PIECE`, `Y_PIECE`); index 14 (`SINGLE_PIECE`) is a bare 1×1 block. `randomPiece()` draws from a weighted table (`SPAWN_WEIGHTS`) rather than a uniform 1-in-8: the seven tetrominoes are weighted 10 each, the Nut 3 (a rare challenge piece), and each pentomino 2 — `SINGLE_PIECE` is deliberately excluded from that table and only ever granted as a reward (see Line clearing below).
- **Collision** (`collide`): checks board bounds and overlap with locked cells.
- **Wall kicks** (`tryRotate`): after rotating, tries x-offsets `[0, -1, 1, -2, 2]` until one doesn't collide, else the rotation is discarded.
- **Game loop** (`loop`): driven by `requestAnimationFrame`, accumulates elapsed time in `dropAccum` and drops the piece one row once `dropInterval` is exceeded, otherwise locks it (`lockPiece` → `merge`/`applyPowerUp` + `resolveBoard` + `spawn`). While `freezeLeft > 0` the drop timer is held at zero instead — see Power-ups below.
- **Line clearing** (`clearFullRows`): scans bottom-up, splices full rows out and unshifts empty rows at the top; re-checks the same row index after a splice (`r++` compensates the loop's `r--`); also reports whether any cleared row contained a `WILD` cell.
- **Board resolution** (`resolveBoard`): wraps `clearFullRows` in a cascade loop — after a clear, if a `WILD` cell was involved, all wildcards are purged (`purgeWild`) and the board is compacted (`applyGravity`) before checking for newly-completed rows again; a wildcard-free clear stops immediately since a plain splice can't create new full rows on its own. Rolls the total cleared into `lines`/`level`/`dropInterval` and returns `{ total, tetris }` — `total` is lines cleared this lock, `tetris` is true if any single pass cleared 4+ rows. `lockPiece` sets `singlePending = true` when `tetris` is true, which makes the *next* call to `randomPiece()` return the `SINGLE_PIECE` (1×1) reward piece instead of drawing from `SPAWN_WEIGHTS` — checked after `powerUpPending` but before the weighted draw, so a Tetris that also charges a power-up still gets its reward on the piece after that.
- **Scoring**: `LINE_SCORES = [0, 100, 300, 500, 800]` multiplied by `level`; hard drop adds 2 points per row dropped, soft drop 1 point per row; power-up effects add their own per-cell bonuses (see below).
- **Leveling/speed**: level increments every 10 lines; `dropInterval = max(100, 1000 - (level - 1) * 90)` ms.
- **Ghost piece** (`ghostY`): projects the current piece straight down to its landing row, drawn (like the current piece and the next-preview) via the shared `drawPiece` helper with `alpha = 0.2`.
- **Game over**: detected in `spawn()` when the newly spawned piece immediately collides — triggers `endGame()` and shows the overlay.
- **Power-ups**: a power-up charges on a hybrid meter, whichever threshold is hit first — `POWERUP_LINES` (3) lines cleared or `POWERUP_PIECES` (12) plain pieces placed. `lockPiece` calls `chargePowerUp(clearedLines, placedPieces)` once per lock (the power-up block itself never counts as a placed piece — its charge was already spent when it was scheduled); when either counter reaches zero, `chargePowerUp` sets `powerUpPending` and resets *both* counters together, so a fast line-clearer and a slow stacker each still get regular power-ups. The next call to `randomPiece()` then returns a 1×1 block (cell value `POWERUP`) tagged with a random key from `POWERUPS` (`bomb`, `bolt`, `dye`, `gravity`, `freeze`) instead of a normal tetromino — it shows up one piece ahead in the NEXT preview, drawn via `drawPowerBlock` with its icon. It never merges onto the board: `lockPiece` detects `current.power` and calls `applyPowerUp(power, x, y)` instead of `merge()`, then still runs `resolveBoard()`.
  - **Bomba** (`blastArea`): clears the 3×3 area centered on the landing cell.
  - **Rayo** (`blastCross`): clears the full row and column through the landing cell.
  - **Tinte** (`dyeWildcards`): finds the most common piece color on the board (any locked color 1–8 or 11–14, via the `isPieceCell` helper — `POWERUP` and `WILD` are excluded) and turns every cell of that color into `WILD` (drawn with `drawWildMark`, an X over the normal block). Wildcards count as filled for line-clear purposes; clearing any row that contains one purges *all* wildcards on the board and re-compacts via `applyGravity`, which can cascade into further clears (`resolveBoard`).
  - **Gravedad** (`applyGravity`): compacts every column independently, dropping all non-empty cells to the bottom with no reordering.
  - **Congelar**: sets `freezeLeft = FREEZE_MS` (5000ms); `loop` counts it down using its own frame `dt` (so pausing with `P` — which cancels the animation frame — doesn't burn freeze time) and skips the auto-drop step entirely while it's active, though manual moves/rotate/hard-drop still work.
  - HUD: `#power-next` shows the two countdowns as `<linesToPower>L · <piecesToPower>P`, `#power-active` shows the last-triggered power-up (with a live countdown while Congelar is active), and `#power-legend` is a static reference built once from `POWERUPS` (`buildPowerLegend`), plus a small `L = líneas · P = piezas` hint.

Tunable constants at the top of `game.js`: `COLS`, `ROWS`, `BLOCK`, `COLORS`, `PIECES`, `SPAWN_WEIGHTS`, `LINE_SCORES`, `POWERUP_LINES`, `POWERUP_PIECES`, `FREEZE_MS`, `POWERUPS`. If `COLS`/`ROWS`/`BLOCK` change, the `<canvas id="board">` width/height in `index.html` must be updated to match (`COLS × BLOCK`, `ROWS × BLOCK`).

- **Skins visuales**: a `SKINS` constant (`retro`/`neon`/`pastel`/`pixel`, each just `{ label }`) drives the `#skin-select` dropdown in the sidebar. `COLORS` is untouched and remains the canonical retro palette (`isPieceCell`/`dyeWildcards` still key off `COLORS.length`); `PASTEL_COLORS` is a separate, index-aligned palette used only by the pastel rendering path. `drawBlock` (`game.js`) branches on the module-level `activeSkin` string and delegates to `drawBlockRetro`/`drawBlockNeon`/`drawBlockPastel`/`drawBlockPixel` — all four keep the same `(context, px, py, colorIndex, size)` shape so `drawPiece`, `draw()`, and `drawNext()` call `drawBlock` exactly as before with no signature changes. Neon sets `ctx.shadowBlur`/`shadowColor` for a glow and resets `shadowBlur = 0` immediately after filling so it doesn't bleed into grid lines or later draws; pastel fills a rounded rect (`roundRectPath`, `ctx.roundRect` with a manual arc-based fallback) using `PASTEL_COLORS`; pixel overlays a 2×2 lighter/darker checker pattern on top of the flat fill; retro is the original flat-fill-plus-highlight-strip behavior, byte-for-byte. The active skin also toggles a `body.skin-<name>` class (clearing the others) so `style.css` can override the same board-specific custom properties the theme toggle uses (`--board-bg`, `--board-border`, `--grid-line`); each non-retro skin deliberately fixes its own board colors (neon/pixel dark, pastel light) regardless of the light/dark theme — those rules intentionally take priority over `body.light-theme` for the board specifically (both are single-class selectors, so the later-declared skin rule wins), while the rest of the page (background, text, panel) still follows the theme toggle independently. `retro` defines no override, so it always matches whatever the theme toggle set. Persisted to `localStorage['tetris-skin']` (`SKIN_KEY`) and restored on load via `applySkin()`/`initSkin()`, mirroring the `THEME_KEY`/`applyTheme()`/`initTheme()` pattern; switching mid-game applies immediately (redraws `draw()` and `drawNext()`) with no reload.
- **Pause menu**: `P` or `Escape` toggles `paused` and shows/hides the `#pause-menu` overlay (a separate DOM block from the game-over `#overlay`) via `togglePause()`. While `paused` is true, the `keydown` handler bails out before the movement `switch` so left/right/rotate/drop are ignored; `P`/`Escape` are handled first and always `return`, so the same keypress that closes the menu never also falls through to a game action. The menu has: **Reanudar** (closes the menu and restarts the loop), **Reiniciar** (calls `init()` directly, no reload), **Ver controles** (toggles the `.hidden` class on a `<ul>` that repeats the sidebar's key list), and a **Nivel inicial** `<select>` (1–15) persisted to `localStorage['tetris-start-level']` (`START_LEVEL_KEY`) via an apply/init pair (`getStartLevel`/`initStartLevelSelect`) mirroring the existing `THEME_KEY` pattern. The saved value is only read into the new module-level `startLevel` state in `init()`, so a mid-game change takes effect on the next game start. `resolveBoard()`'s leveling formula is `level = startLevel + Math.floor(lines / 10)`, and `dropInterval` is derived from `level` the same way in both `init()` and `resolveBoard()`, so starting above level 1 also starts at the correspondingly faster drop speed.
- **Tabla de records local**: persisted in `localStorage` under three keys — `tetris-scores` (array of up to `MAX_SCORES` (5) `{ name, score, lines, level }` entries, kept sorted descending by score), `tetris-best-combo` (integer, the highest streak of consecutive piece locks that each cleared ≥1 line), and `tetris-max-lines` (integer, the max lines cleared by a single lock). `lockPiece()` updates the combo streak and max-lines record right after `resolveBoard()` returns `cleared`: `cleared > 0` increments the running `comboStreak` (and bumps `tetris-best-combo` if it's a new high), `cleared === 0` resets `comboStreak` to zero; `tetris-max-lines` is bumped whenever `cleared` exceeds it. A `#start-screen` overlay (new markup, styled like `#overlay`) is shown on page load and gates the game: `init()` — and therefore the `requestAnimationFrame` loop and all keyboard input — only runs once the player clicks **Jugar** (guarded by the `started` flag, checked first thing in the `keydown` listener). Both the start screen and the existing game-over `#overlay` render the same top-5 table (`renderRecords`/`renderScoresList`) plus the best-combo/max-lines stats, and both expose a "Resetear records" button (`resetRecords`, confirm-gated) that clears all three keys. On game over, `endGame()` checks `qualifiesForTop(score)`; if the score would place in the top 5 it reveals a name input + save button (`#save-score`) that calls `insertScore()` to splice the new entry in, re-renders the table, and highlights the inserted row (`.new-record`).
